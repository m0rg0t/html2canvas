# Library maintenance and remaining migration work

This draft modernizes the root library's build, typecheck, Jest/ESLint and browser verification toolchain. It is not completion of the entire repository migration. The website moves to Gatsby 5.16.1 and React 18.3.1 while retaining Glamor styles, content, images and route/link contracts. Its obsolete Gatsby Glamor wrapper is replaced with equivalent Babel/SSR/rehydration hooks, and Gatsby Link/GraphQL and Helmet imports use current APIs. Historical verification jobs now use supported Actions, Node 24 and hosted runner labels. Publisher jobs, triggers and the release workflow remain unchanged.

## Verified contracts

- Contributor Node 24 is separate from the published Node >=8 contract. CI checks the CommonJS bundle on Node 8.17, while parser tests enforce ES5 syntax for both UMD distributions. Disabling UglifyJS's new arrow-function conversion fixes a reproduced minified-output regression.
- UMD/CommonJS, ESM, declarations and source maps retain their entry points. Rollup uses native ESM configuration files and TypeScript 5.9. Jest 30 and ts-jest 29.4 use compatible declared peers. TypeScript 7 is outside ts-jest's peer range and the retained ES5 compilation contract.
- All 110 original unit assertions are retained. Deprecated Jest matcher aliases use their current equivalent. Existing screenshot baselines are untouched. Additional CI compares two synthetic fixtures pixel-for-pixel against a separately built, pinned original commit, in both regular and minified output, and runs the existing Karma fixtures in Chrome, Firefox and native Safari.
- Production source changes are formatting, an explicit `void` property read, and a comment retaining the existing Hebrew/Gurmukhi enum collision. Correcting that numeric/rendering behavior requires focused fixtures and is not hidden inside the tooling update.
- The obsolete sourcemaps plugin pulled a Rollup-2-only helper into the Rollup 4 graph. TypeScript and Rollup now produce source maps directly; artifact tests check the original TypeScript sources and embedded source content.

## Dependency findings (2026-10-03)

The refreshed root audit has 32 findings (12 high, 20 moderate), with no critical findings. It previously reported six critical entries. Scoped replacements address these paths:

- `chromeless -> chrome-launcher -> mkdirp/minimist`: launcher 1.2.2 removes the vulnerable launch/argument-parsing chain. The current 0.34 CDP transport preserves the used `goto/evaluate/end` contract; a local synthetic browser smoke check is part of CI.
- `html2canvas-proxy -> request -> form-data`: compatible form-data 2.5.6 preserves multipart length/output behavior and rejects header injection through field/filename data in regression checks.

This is not a clean full audit. Retained Chromeless/AWS SDK 2, the legacy proxy/request stack, native simulator helpers and parts of the release-tool dependency graph still require targeted migrations. The preview now uses Webpack 5.111.1, CLI 7.2.3 and ts-loader 9.6.2 with an ES5 target. Direct glob 13 uses its own types and retains sorted fixture enumeration. Unused direct build dependencies were removed; standard-version is updated to 9.5.0 without running any release command. `braces` GHSA-vfj7-8cjw-p6xm has no published patch; no override claims to fix it. Tests use repository-controlled patterns and synthetic fixtures. No remote Chromeless/AWS service is invoked.

The refreshed `www` graph reports 73 findings (49 high, 12 moderate, 12 low) and no critical entries, down from the previously published 157 findings and the original 206 findings including 22 critical. Both independent frozen installs pass without peer bypass. This remains a qualified audit, not a clean graph.

A candidate upgrade to karma-sauce-launcher 4.3.6 initially reintroduced critical archive-extraction findings through SauceLabs 4 / bin-wrapper / download / decompress. A scoped SauceLabs 8.0.0 override removes that path in favor of its compressing implementation. Isolated regressions exercise the installed SDK's job update, asset download/upload, SC4 tunnel-identifier adaptation and close lifecycle, with HTTP, binary downloads and child-process creation replaced by synthetic fixtures. No provider credentials or real Sauce session are used. Current SauceLabs 9 explicitly removes SC4 support, so it is not substituted blindly for the launcher's retained SC4 contract.

Gatsby 5 eliminates the former git-up/parse-url, GraphQL URL-loader and Contentful vulnerability paths; tests assert their absence in the new lockfile. The website's actual multipart encoder still receives the header-injection regression, and current React Dev Utils diagnostics and argument quoting remain checked. Old overrides for eliminated packages were removed. A dependency-free copy helper replaces cpy/mkdirp and checks original source paths, file filters and overwrite behavior. React 19 remains outside the retained react-typography 0.16.23 peer contract.

Website CI builds the immutable original and current graphs, blocks external analytics/ads/fonts requests, and compares nine routes at desktop/mobile widths. It feeds both reftest previewers the same synthetic browser artifacts. Only the displayed bundle-size statistic is normalized because the rebuilt library's byte size legitimately changes. No existing screenshot baseline is replaced. Gatsby telemetry is disabled for installs/builds. The exact-head website comparison job must pass; the pull request records the verified run and results.

## Remaining work and concrete acceptance criteria

1. Require exact-head frozen installs, all 110 original unit assertions, library build/type/lint checks, ES5/CJS/ESM/declaration/source-map checks and preview builds. The renewal passes these local checks. Local Chromium is blocked by the execution environment's socket restrictions; the current-head GitHub verification is the authoritative browser acceptance gate. A successful build alone is not a visual-equivalence claim.
2. Require all 18 exact website content/link/PNG comparisons plus hydration, mobile menu open/close/reopen, client navigation/Back and repeated capture/close interactions. CI preserves successful screenshots as review artifacts as well as diagnostics. Gatsby telemetry is disabled, and browser tests block analytics/ads/fonts requests. The inherited Universal Analytics property is retained; no replacement GA4 property is invented. Check the PR for the latest exact-head result.
3. Remaining legacy Chromeless/AWS, proxy/request and simulator dependencies need focused migrations with their original APIs and browser targets preserved. The obsolete create-reftests utility references a removed RefTestRenderer; it has not been silently deleted to improve audit counts. No remote services or publishing commands are invoked to test these tools.
4. The historical workflow retains all 11 original browser targets. Windows 2022 still provides IE emulation; Mocha 12 needs an ES5 transform and framework-only polyfills there. A regression checks ES5 parsing and actual Promise assertions with legacy globals. Renderer bundles and fixture iframes are not transformed or globally polyfilled by this adapter. The screenshot uploader retains pending XDomainRequest objects, registers all lifecycle handlers and defers legacy sends to prevent the reproduced zero-byte aborts; synthetic tests check standard/legacy success, repeated requests, HTTP errors, timeouts and send exceptions. The served dependency list is bounded to prevent Windows file-handle exhaustion. The five iOS 12–15 targets require Xcode 10.3, 11.7, 12.4, 13.0 and 13.2, which supported hosted macOS runners do not provide. They fail an explicit availability check without skipping or substituting their assertions. Those checks require a provisioned legacy macOS environment or an explicit support-policy change; current desktop browser results do not certify old iOS.
5. Historical read-only artifact producers and consumers now use the supported artifact protocol with unique per-browser names and merged results. The original docs/diff dependency on the complete browser matrix is preserved, so unavailable iOS targets still block those jobs. The separate current verification pipeline builds and checks the website. Unchanged publisher jobs still use retired download-artifact v2 and cannot consume modern artifacts; publication requires its own approved migration before any release/deployment attempt. No publisher execution is part of this draft.

Current read-only Actions are pinned to verified commit SHAs. Both publisher job sections, the historical trigger prefix, and all of `.github/workflows/release.yml` remain byte-for-byte unchanged. Only the historical build/test/browser/docs/diff jobs were modernized with read-only permissions and no-script/no-audit installs. The added verification workflow also has read-only repository permissions and performs no release or deployment. The original historical workflow remains red while its required old iOS environments are unavailable; repository maintenance is incomplete.
